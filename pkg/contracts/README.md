# Contract bindings

This directory holds bindings generated by abigen v1, which wrap each contract in `Caller`, `Transactor` and `Filterer` types bound to an address and a backend.

[`v2`](v2) mirrors the same tree with bindings generated by `abigen --v2`.
These are stateless `Pack`/`Unpack` helpers used with go-ethereum's [`accounts/abi/bind/v2`](https://pkg.go.dev/github.com/ethereum/go-ethereum/accounts/abi/bind/v2) functions `Call`, `Transact`, `FilterEvents` and `DeployContract`.
Here `v2` is the abigen binding format.
It is not a version of the Flare contracts or of this module, and both trees are in the same module.

Packages have the same names in both trees, so alias one when importing both:

```go
import (
	"github.com/ethereum/go-ethereum/accounts/abi/bind/v2"
	relayv1 "github.com/flare-foundation/go-flare-common/pkg/contracts/relay"
	"github.com/flare-foundation/go-flare-common/pkg/contracts/v2/relay"
)

r := relay.NewRelay()
root, err := bind.Call(r.Instance(client, addr), nil, r.PackGetConfirmedMerkleRoot(protocolID, roundID), r.UnpackGetConfirmedMerkleRoot)
```

## Packages

Outside `tee`, each package binds the contract of the same name, except:

| Package            | Go type               | Contract                     |
| ------------------ | --------------------- | ---------------------------- |
| `calculator`       | `Calculator`          | `FlareSystemsCalculator`     |
| `contractregistry` | `ContractRegistry`    | `FlareContractRegistry`      |
| `fumanager`        | `FUManager`           | `FastUpdateIncentiveManager` |
| `fupdater`         | `FUpdater`            | `FastUpdater`                |
| `offers`           | `Offers`              | `FtsoRewardOffersManager`    |
| `preregistry`      | `Preregistry`         | `VoterPreRegistry`           |
| `registry`         | `Registry`            | `VoterRegistry`              |
| `system`           | `FlareSystemsManager` | `FlareSystemsManager`        |

Most `tee` packages bind a `<Name>Facet` of the `FlareTeeManager` diamond (EIP-2535), so call them at the diamond's address.
The exceptions are `flareteemanagerinit`, the diamond's init contract, and `teepayments*`, `teerewardoffersmanager` and `vrfverifier`, which are standalone contracts.
Of these, `teepaymentsbase` is only the abstract base of `teepayments` and `teepaymentsutxo`, so it has no address of its own.

## Deploying

Only `tee/vrfverifier` embeds deployment bytecode, so it is the only binding that can deploy its contract:

```go
// v1
addr, tx, v, err := vrfverifierv1.DeployVRFVerifier(opts, client)

// v2
addr, tx, err := bind.DeployContract(opts, common.FromHex(vrfverifier.VRFVerifierMetaData.Bin), client, nil)
```

## Updating ABIs

ABIs come from the Hardhat artifacts of `flare-smart-contracts-v2`, except `contractregistry`, which comes from `flare-smart-contracts`.

[`abi_update.sh`](../../abi_update.sh) copies the `tee` and `fdc2` ABIs, the `vrfverifier` bytecode and the struct ABIs of [`pkg/tee/structs`](../tee/structs).
It expects a checkout compiled with `pnpm hardhat compile` at `../../fsp/flare-smart-contracts-v2`, relative to the repo root.
It skips missing artifacts with "File not found" and still exits 0, so check its output.

Other ABIs are copied by hand from the artifact's `abi` field (`jq .abi <artifact>.json`).
`entitymanager`, `preregistry` and `registry` use the interface artifacts `IEntityManager`, `IVoterPreRegistry` and `IVoterRegistry`.

## Regenerating

```sh
go generate ./pkg/contracts/...
```

`go generate ./...` from the repo root also regenerates `pkg/tee/structs`.

The v2 directives run a pinned abigen through `go run`.
The v1 directives run `abigen` from `PATH`, so install the same version first:

```sh
go install github.com/ethereum/go-ethereum/cmd/abigen@v1.17.2
```

The v2 bindings read their ABIs from the v1 directories, so both trees regenerate from a single ABI copy.
Regenerating needs `jq`, which renames parameters that abigen v2 would turn into invalid Go in `offers` and `fdc2requestfeeconfigurations`.
The renames do not change the encoding.

## Adding a contract

1. Put the ABI at `<name>/<name>.abi`, under `tee/` or `fdc2/` for those contracts, where `<name>` is the lowercased contract name without a `Facet` suffix.
   For `tee` and `fdc2`, add the artifact to `CONTRACTS` in `abi_update.sh`, and to `BIN_CONTRACTS` if it needs bytecode, then run the script.
2. Add `<name>.go` next to the ABI with the v1 directive, copied from a sibling, plus `--bin=<name>.bin` for bytecode.
3. Add the same path under `v2/` with the v2 directive, pointing `--abi` (and `--bin`) back at the v1 files.
4. Run `go generate ./pkg/contracts/...`.
   If the v2 output does not compile, rename the offending parameters with `jq` as in `v2/offers`, and add a test that both trees pack the same calldata.
5. If the package name differs from the contract name, add it to the table under [Packages](#packages).
